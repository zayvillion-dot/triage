# Design: triage (2026-11-01)

## Origin

A house protocol in force since October 2026: one chat takes the owner's mixed batch of answers and findings and only records, routes, and hands out. Ticks on a tracker mean "do the default as written". Small work is done in that chat by a subagent; everything larger gets its own session and a build prompt. The skill generalizes the protocol so any agent runs a batch the same way.

## Form

This is a shaping and routing problem, not a discipline problem. Without the skill, an agent answers inline, builds the first thing in the same chat, loses answers, and never ranks. So the skill is a recipe with a small decision table for lane sizing (Quick, Standard, Critical). There is no long prohibition list; the common-mistakes table covers the failure modes.

## Recipe rationale

- Record first, so no answer lives only in chat.
- Priority numbers force an order the owner can act on.
- Self-contained build prompts let a fresh session start cold.
- The ledger closes every pass, so the owner sees what is done and what they owe.
- Live decisions are flagged, not absorbed, because they need back-and-forth.
- Rollover through a handoff file keeps a long triage chat from degrading.
